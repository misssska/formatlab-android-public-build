# FormatLab P0g review — 2026-10-25

## Scope and evidence

Reviewed the current P0g development branch's Java Office worker, Binder client,
native package composer, source ZIP overlay, APK gate, synthetic tests and CI.
Pinned upstream LibreOfficeKit Java declarations were checked at
`LibreOffice/core@f2820323446ae210668dcb6422ddcd55ce939dc2`.
The original FormatLab Android v0.3 source SHA256 remains
`04694a0afbc26ebcbe7dd0c4c265d656acc05497d6d5765980c22e4366c0123b`.

**The review does not certify the native Android runtime or fidelity.**
P0c #5 produced a verified ARM64 shared library; P0c #6
(GitHub Actions run `40214977279`) is intended to retain the separate upstream
LibreOffice reference APK. P0g cannot certify a real installable FormatLab APK
until that artifact, its resource contents, and all 14 native libraries are
qualified. Do not modify or publish the known-working v0.3 or main.

## Confirmed findings and changes

| Risk | Finding | Fix / validation |
| --- | --- | --- |
| Hang | A bound Office client had no own deadline if the remote service stayed silent | Client deadline at worker timeout + 20 s; cancel deadline on completion; targeted source contract test |
| Invalid PDF | A header-only file over 100 bytes could be accepted | Require an EOF marker within the final 64 KiB as well as the PDF header and existing size limits |
| DOCX ZIP ambiguity | Noncanonical names such as dot segments, double slashes and NUL could pass some input checks | Reject before native parsing; source guard test |
| Cache exhaustion | Stale Office input/output files could survive a process crash and accumulate | On a new conversion remove only known private temporary filenames older than 24 h; source guard test |
| ZIP extraction aliases | Source archive and APK ZIP checks did not uniformly reject names that normalize to a different path | Reject noncanonical ZIP paths, with synthetic negative tests |

The DOCX ZIP filters and EOF checks are defense in depth: **not** proof that a
malicious document cannot exploit LibreOffice, and **not** proof of valid PDF
structure beyond the limited checks. The cache cleaner is best-effort and only
runs on a subsequent conversion.

## Checks already available

- The original offline v0.3 source is pinned by SHA256.
- The Office Android service runs in a separate, nonexported `:office` process.
- Work is dispatched from Binder to a background worker with a 180 s watchdog.
- Terminal results use a shared atomic completion latch.
- The APK static gate checks declared permissions, arm64 native headers,
  all 14 libraries, assets, fonts and entry limits.
- The native composer compares library hashes against the upstream reference APK
  and rejects failed native evidence.
- Synthetic regression tests and the isolated Android Gradle build run in CI.

## Unresolved release blockers

1. Receive P0c #6 completed artifact, verify GitHub job result, artifact provenance,
   its SHA256, reference APK presence, all 14 native libs and exact source revision.
2. Run **actual** `compose_native_office.py` with pinned v0.3, pinned Java
   upstream checkout, real P0c evidence, native libs and reference APK.
   Do not bypass missing fonts, registry, bootstrap or license checks.
3. Build the *composed* FormatLab APK, run `offline_apk_gate.py`, and inspect
   the compiled manifest, ABI, native compression/extraction, size and permissions.
4. Install on an actual ARM64 Android device, **airplane mode**, and validate
   import / export, JNI startup, normal and malformed DOCX, timeout, kill/restart,
   low storage, memory pressure, repeated conversions and file cleanup.
5. Run the five P0e fidelity documents for table, typography, graphics,
   page breaks and complex layout; compare output against offline reference PDFs.
6. Verify all LibreOffice, font and third-party dependency license notices before
   any public APK distribution.

## Acceptance and rollback

Do not merge or release based solely on green synthetic CI. Any failed native
runtime, missing resource, unverified license or document-fidelity gate must
block release. The working main/v0.3 remains the rollback baseline. A clean
candidate should retain the source commit, P0c evidence, original asset hashes,
APK SHA256 and reproducible test outcomes.
